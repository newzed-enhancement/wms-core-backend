## 1. 작업 장소가 바뀌었습니다

| | 위치 |
|---|---|
| **앞으로 개발할 곳** | `github.com/newzed-enhancement/wms-core-backend`<br>`github.com/newzed-enhancement/wms-core-frontend` |
| 기존 팀 레포 | 제출 시점 상태로 **동결**. 여기서 새 작업을 시작하지 마세요 |

기존 레포는 평가·포트폴리오 근거로 그대로 둡니다. 새 레포는 포크라 커밋 이력이
전부 이어져 있고, 기존 레포에 영향을 주지 않습니다.

**첫날 할 일**

1. 조직 초대 수락 → 새 레포 clone (기존 로컬 폴더를 재사용하지 말고 새로 받는 걸 권합니다)
2. [README](../README.md)의 **시작하기** 절차대로 기동
   - `.env` 필요 항목은 [로컬 개발 가이드](Team_Local_Dev_Guide.md)에 있습니다
   - **YOLO 가중치 4종은 Git에 없습니다.** `models/` 폴더에 직접 넣어야 하고,
     없으면 검수 요청이 실패합니다 ([models/README.md](../models/README.md) 참고)
3. `docker compose up -d --build` → `docker compose run --rm rag-seed` (최초 1회)
4. 확인: API `localhost:8080/docs`, Flower `localhost:5556`

> 포트가 예전과 다릅니다 — DB **5433**, Redis **6380**, Chroma **8002**, API **8080**.
> 다른 트랙과 충돌하지 않도록 분리한 값입니다. 예전 문서에 8000/5432로 적힌 게 있으면
> 그건 구버전입니다.

## 2. 내가 알던 파일이 어디로 갔나

**로직은 바꾸지 않고 위치만 옮긴 것이 대부분입니다.** 그리고 기존 임포트 경로가 깨지지
않도록 재수출(re-export)을 남겨 뒀으니, 예전 방식 `import`도 당장은 그대로 동작합니다.

| 예전 | 지금 |
|---|---|
| `app/api/routes/*.py` (21개)<br>`app/services/*.py` (36개)<br>`app/schemas/*.py` (15개) | `app/domains/<도메인>/` **12개 폴더**<br>auth · admin · books · dev · inbound · inspections<br>inventory · lpn · notifications · orders · pricing · restock |
| `app/ai/agents.py` (3,708줄) | `app/ai/agents/` — `detector` `vision` `policy` `critic`<br>`report` `human` `common` `schemas` |
| `app/models/wms.py` (단일 파일) | `app/models/` 11개 모듈로 분할<br>(`wms.py`는 전부 재수출하므로 기존 임포트 유지됨) |
| `app/worker.py` | `app/worker/` 패키지 |
| `app/services/langgraph_wrapper.py` | `app/ai/` 로 이동 (`app/services` 패키지 소멸) |
| DB 세션·설정·보안·Redis 등 횡단 코드 | `app/core/` |

**왜 이렇게 했나**: 예전에는 "반품 검수" 하나 고치는 데 라우터·서비스·스키마 세 폴더를
오가야 했습니다. 파일이 70개를 넘긴 시점부터는 그 탐색 비용이 계층형 구조의 이점보다
커졌다고 판단했습니다. 이제 한 도메인은 한 폴더 안에서 끝납니다.

`agents.py`는 더 현실적인 이유입니다 — **한 파일에 Vision·Policy·Critic·Report가 전부
들어 있어 두 사람이 동시에 손대면 반드시 충돌**했습니다.

## 3. 기능적으로 달라진 것

### AI 검수 판정 — 안전장치가 들어갔습니다 (가장 중요)

| 변경 | 내용 |
|---|---|
| **MINT Fast-track 제거** | 상태 좋은 도서가 Policy·Critic을 건너뛰고 바로 승인되던 지름길을 없앴습니다. **VLM이 인증 오류(401)를 뱉자 전 도서가 최고 등급으로 오승인된 실제 사고**가 근거입니다. 지금은 전 건이 같은 검증 경로를 지납니다 |
| Supervisor 판단 주체화 | 정해진 순서대로 도는 게 아니라, 상태를 보고 다음 노드를 고릅니다 |
| 판독 커버리지 게이트 | 이미지 판독 범위가 기준에 못 미치면 자동 승인하지 않고 HITL로 넘깁니다 |
| Report Agent | 고객 보증서 문구를 LLM이 씁니다. **LLM이 실패하면 기존 결정론적 문구로 폴백**합니다 |
| 노드 계측 | 구간별 지연·토큰·비용을 수집해 `agent_logs`에 남깁니다. 계측이 실패해도 판정은 막지 않습니다 |
| HITL → 판례 축적 | 관리자가 확정한 판단이 Critic의 참고 판례로 쌓여 다음 검수에 근거로 쓰입니다 |

검수 1건 비용은 실측 기준 **약 $0.019 / 80,373 토큰**입니다.

### 보안

- **presign 라우트가 인증 없이 S3 쓰기 URL을 발급하던 문제**를 막았습니다
  (인증 필수 + content-type 화이트리스트)
- CORS 오리진 환경변수화, `weekly_insights` 테넌트 격리, 개발용 더미 재고 API 제거

### 운영

- `.dockerignore` 추가 — 1.3GB `.venv`와 250MB `models/`가 빌드 컨텍스트에 딸려 들어가
  **Docker 빌드가 사실상 멈춰 있던** 문제를 해결했습니다
- Chroma 헬스체크가 항상 실패하던 것 수정, 의존 서비스를 "떴는지"가 아니라
  "정상인지"(`service_healthy`) 기준으로 승격
- RAG 시딩을 `rag-seed` 서비스 하나로 일원화

### 문서

- 양 레포 README 재작성
- **API 명세서를 코드에서 자동 생성**합니다 (`scripts/generate_api_spec.py`,
  현재 70개 엔드포인트 / 18개 태그 → `docs/API_Specification.md`).
  수기 명세서는 반드시 코드와 어긋나므로 더 쓰지 않습니다

## 4. 지켜 주셔야 할 것

### 브랜치와 PR

- `main` 직접 푸시 금지. `feat/` `fix/` `refactor/` `docs/` `chore/` 접두사 사용
- PR을 올리면 품질 게이트가 자동으로 붙습니다

### 품질 게이트 — 우회하지 마세요

로컬에서 먼저 돌려 보고 올리시면 왕복이 줄어듭니다.

```
# 백엔드
uv run ruff check app/ && uv run ruff format --check app/
uv run mypy app/
uv run pytest -q

# 프론트엔드
npm run lint && npm test && npm run build
```

**부탁**: 게이트가 빨갛다고 `|| true`나 `continue-on-error`를 붙이지 마세요.
이번 작업의 상당 부분이 그렇게 무력화돼 있던 게이트를 되살리는 일이었습니다.
착수해서 열어 보니 게이트가 느슨한 정도가 아니라, 백엔드는 `ruff`·`mypy`가 의존성에
아예 없어서 **해당 단계가 한 번도 실행된 적이 없었습니다.**

린트 규칙을 무시해야 한다면 `pyproject.toml`에 **사유와 함께** 적어 주세요.
기존 무시 항목도 전부 사유가 적혀 있습니다.

### 손대기 전에 상의가 필요한 곳 (코드 프리즈 구역)

**AI 4-Agent 파이프라인 구조와 모델 배정**입니다.
(Vision = GPT-4o, Policy·Critic·Report = GPT-4o-mini)

- 4단계를 한 에이전트나 한 프롬프트로 합치지 않기
- 모델 배정 바꾸지 않기 — 비용 최적화와 단계별 감사 추적성이 걸려 있습니다

바꿔야 할 이유가 생기면 **실측 근거를 정리해서 먼저 이야기해 주세요.**
지금까지의 예외 승인 이력은 `.claude/rules/01-freeze-zones.md`에 남아 있습니다.
파일 분할·이동처럼 로직이 그대로인 변경은 구조 변경으로 보지 않습니다.

### 문서

코드를 고치면 **같은 PR 안에서** 관련 문서도 고쳐 주세요. "나중에 문서화"는 안 됩니다.

## 5. 알려진 함정 (전부 실제로 겪은 것)

미리 알면 몇 시간씩 아낍니다.

| 증상 | 원인 / 대응 |
|---|---|
| Docker 빌드가 끝나지 않음 | 빌드 컨텍스트에 `.venv`·`models`가 들어가는 경우. `.dockerignore`가 있는지 확인 |
| 검수가 모델을 못 찾음 | `models/`에 YOLO 가중치 4종이 있는지 확인. Git에 없습니다 |
| 컨테이너는 떴는데 RAG가 비어 있음 | `docker compose run --rm rag-seed`를 안 돌린 경우 (최초 1회 필요) |
| CI에서만 테스트가 무더기로 깨짐 | 테스트가 로컬 `.env`에 의존하면 안 됩니다. 필요한 값은 `tests/conftest.py`에서 주입합니다 |
| CI `npm ci` 실패 | **Windows에서 만든 `package-lock.json`은 플랫폼별 optional 의존을 빠뜨립니다.** lock을 갱신해야 하면 Linux 환경(예: `node:20-alpine` 컨테이너)에서 만들어 주세요 |
| 호스트 테스트는 통과인데 Docker에서 깨짐 | 호스트 테스트는 YOLO를 목(mock)으로 대체합니다. **경로·모델 로딩 문제는 Docker E2E에서만 드러납니다.** 관련 변경은 반드시 컨테이너에서 확인하세요 |
| 컨테이너에서 직접 `pip install`로 고침 | 컨테이너를 다시 만들면 사라집니다. **의존성은 이미지 재빌드로 검증**해야 합니다 |

| 순서 | 항목 | 내용 | 주의 |
|---|---|---|---|
| 1 | **가격 예측 모델 도입** | 판매 확률(p_sold) 산출을 규칙 산식에서 학습 모델 추론으로 교체. 기존 가격 에이전트는 유지하고 **산출부만** 교체. 모델이 없으면 기존 산식으로 폴백 | 합성 데이터 명세와 DB 스키마 정합 확인 선행 |
| 2 | **탐지 앙상블(WBF)** | 여러 탐지 모델 결과를 가중 융합해 정확도 향상 | **융합 가중치는 반드시 재실측**해서 정합니다. 다른 학습셋에서 얻은 값을 그대로 가져오면 안 됩니다. 초기값으로 두고 실촬영 셋 A/B 후 확정 |
| 3 | **3D 적재 최적화** | 다건 주문 시 최적 박스 적재 가이드 + 프론트 3D 시각화 | 도서 물리 치수 컬럼 시딩이 선행돼야 합니다. 프론트는 `react-three-fiber` 의존성이 이미 있습니다 |

**당분간 하지 않기로 한 것**: 프론트 FSD 전면 전환(비용 대비 이득 없음), PWA·Sentry(운영 전환 시 재검토)

### 아직 확인되지 않은 것

정확히 알고 계시라고 적어 둡니다.

- **AWS/EKS 배포 경로**: 배포 매니페스트가 없고 워크플로의 `kubectl` 라인이 주석 처리돼
  있습니다. 배포는 검증된 적 없습니다
- 실촬영 데이터셋 기준 AI 판정 정확도 — 샘플 이미지로만 확인
- 부하·동시성 테스트 미실시

**검증된 것**: Docker E2E 전 구간(로그인 → 도서 등록 → 중고 입고 → 업로드 → AI 검수 →
HITL → 승인 → 재고 반영)과 양 레포 CI 그린은 실측으로 확인했습니다.
